# A* PathFinding 최적화

## 1. 프로젝트 개요

A* 길찾기를 구현하는 데 그치지 않고, 성능을 공정하게 측정할 수 있는 환경을 만든 뒤 단계별로 최적화한 프로젝트입니다. 랜덤 장애물 그리드에서 A*를 반복 측정하되, BFS로 경로 존재를 먼저 보장해 측정 조건을 통제했습니다. 그 위에서 휴리스틱 변경, 캐시 지역성 개선, 분기 제거를 단계별로 적용하고 각 단계의 처리 시간을 비교했습니다. 즉 알고리즘 구현보다 **측정 조건 설계와 측정 기반 최적화**가 핵심인 프로젝트입니다.

## 2. 테스트 설계

측정 결과를 신뢰할 수 있도록 조건을 통제한 것이 이 프로젝트의 핵심입니다.

- 매 반복마다 확률 기반으로 장애물을 배치한 랜덤 그리드를 생성합니다.
- 시작점과 도착점은 벽이 아닌 빈 칸에서 무작위로 선정합니다.
- BFS로 시작점에서 도착점까지 경로가 존재하는지 먼저 확인합니다.
- 경로가 없으면 그 케이스는 버리고 맵을 새로 생성합니다. 즉 경로가 존재하는 경우에만 A*를 측정합니다.
- BFS 검증 시간은 A* 측정 구간에 포함되지 않도록 분리했습니다.
- 위 조건으로 5만 회를 반복 측정해 표본을 확보하고, 극단값을 제외한 평균으로 비교했습니다.

## 3. A* 처리 흐름

README에서는 핵심 흐름만 요약합니다. 함수 단위 상세는 `docs/Code_Flow.md`로 정리합니다.

- open list(우선순위 큐)에서 f 값이 가장 작은 노드를 꺼내 확장합니다.
- 이미 확정된 노드는 close 처리해 다시 열지 않습니다.
- 이웃마다 g(시작점까지 비용), h(도착점까지 추정 비용), f(g + h)를 계산합니다.
- 각 칸에 부모 좌표를 기록해, 도착 후 부모를 거슬러 올라가며 경로를 복원합니다.

## 4. 최적화 과정

| 단계 | 변경 내용 | 목적 |
|---|---|---|
| 1. 휴리스틱 변경 | 유클리드 거리 휴리스틱을 8방향 이동 비용(직선 1, 대각 1.5)에 맞는 옥타일 형태 `h = (dx+dy) - 0.5*min(dx,dy)` 로 변경 | 격자의 실제 최소 비용과 일치하는 추정으로 불필요한 노드 확장 감소 |
| 2. 캐시 지역성 개선 | 격자 데이터 구조 크기를 줄이고, 2차원 배열을 연속 메모리로 배치 | 인접 칸 접근 시 캐시 적중률을 높여 순회 비용 감소 |
| 3. switch 제거 | 8방향 처리를 switch 분기에서 방향 오프셋·비용 테이블 참조로 변경 | 반복 루프에서 분기 비용을 줄임 |

각 단계를 아래 흐름으로 정리하면 다음과 같습니다.

- **휴리스틱 변경** — 문제: 유클리드는 격자 제약이 없는 직선거리라 8방향 이동의 실제 최소 비용보다 낮게 추정함(수평·수직을 제외한 전 구간, 최대 약 12%). 낮게 추정한 만큼 A*가 목표 방향에서 옆으로 더 퍼짐. 변경: 같은 비용 모델(직선 1, 대각 1.5)에서 실제 최소 비용과 일치하는 옥타일 형태로 교체. 결과: 평균 처리시간 감소. 의미: 두 휴리스틱 모두 admissible이라 나오는 경로는 같고, 차이는 확장하는 노드 수에서 발생함.
- **캐시 지역성 개선** — 문제: 격자 데이터가 흩어져 있어 캐시 미스가 잦음. 변경: 구조체 크기 축소 + 연속 메모리 배치. 결과: 추가 감소. 의미: 알고리즘뿐 아니라 메모리 배치도 성능에 영향.
- **switch 제거** — 문제: 8방향 처리를 매번 분기로 판단. 변경: 방향·비용 테이블 참조로 분기 제거. 결과: 추가 감소. 의미: 반복 루프에서 분기 제거 효과가 누적됨.

## 6. 휴리스틱 A/B 검증 — 확장 노드 수로 원인 확인

4장 1단계(휴리스틱 변경)가 왜 효과가 있었는지를, 최적화가 모두 끝난 최종 빌드에서 다시 검증했습니다. 같은 실행·같은 맵·같은 시작/도착점에 대해 h만 옥타일 ↔ 유클리드로 바꿔 번갈아 돌리고, 처리시간과 함께 **확장 노드 수**(우선순위 큐에서 뽑혀 실제로 8방향을 펼친 노드 수)를 셌습니다.

| 휴리스틱 | 확장 노드 수(누적) | 1회당 평균 확장 노드 | 평균 처리시간 | 
|---|---:|---:|---:|---:|
| 유클리드 | 37,823,399 | 약 756개 | 215.6μs | 
| 옥타일 | 31,352,137 | 약 627개 | 180.8μs | 
| 차이 | −6,471,262 (−17.1%) | −129개 | −34.8μs (−16.1%) | +1.2% |

- 5만 회 반복, 상·하위 극단값 제외 기준입니다. 근거 파일: `길찾기 측정 자료/측정 자료/기본/휴리스틱 알고리즘 변경/Profiling [PathFinding_Euclid 37823399_Octile 31352137]_20260826_21.30.59.txt`
- 5장의 4단계 사다리(280.4 → 195.9μs)와는 다른 빌드에서 측정한 별도 실험이므로, 수치를 이어 붙이지 않고 따로 둡니다.

### 6.1 왜 차이가 나는가

h는 그 노드에서 목적지까지의 **이동 거리** 추정입니다. 8방향 격자에서 실제 이동은 대각(1.5)과 직선(1)의 조합이므로,

- 옥타일 `h = (dx+dy) − 0.5·min(dx,dy)` 는 대각으로 min(dx,dy)번, 직선으로 |dx−dy|번 간 비용의 합과 정확히 같습니다. 즉 **장애물이 없을 때의 실제 최소 비용**입니다.
- 유클리드 h는 격자 제약이 없는 두 점 사이의 직선 거리라 항상 그보다 작거나 같습니다.

| 두 점 | 옥타일 h | 유클리드 h | 차이 |
|---|---:|---:|---:|
| (1,1) → (2,2) | 1.5 | 1.414 | 0.086 |
| (1,1) → (3,3) | 3.0 | 2.828 | 0.172 |
| (1,1) → (5,5) | 6.0 | 5.657 | 0.343 |

f = g + h이므로 **목적지에서 먼 노드일수록 f가 더 많이 깎입니다.** 그만큼 실제보다 유망해 보여 우선순위 큐에서 먼저 뽑히고, 탐색이 목적지 쪽으로 가는 대신 옆으로 퍼지는 경향이 있습니다. 확장 노드 수가 늘어나는 원인이 이것입니다. 

## 7. 최적화에서 확인한 점

- 경로가 없는 케이스가 섞이면 A*가 전체 격자를 탐색하는 최악 상황이 표본에 들어가 측정이 오염됩니다. 그래서 BFS로 먼저 걸렀습니다.
- 메모리 배치와 캐시 지역성도 실제 성능에 영향을 줍니다.
- 분기 제거는 반복 루프에서 효과가 누적됩니다.
- 최적화는 감이 아니라 단계별 측정으로 판단해야 한다는 점을 확인했습니다.
