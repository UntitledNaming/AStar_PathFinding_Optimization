# A* PathFinding 최적화

## 1. 프로젝트 개요

A* 길찾기를 구현하는 데 그치지 않고, 성능을 공정하게 측정할 수 있는 환경을 만든 뒤 단계별로 최적화한 프로젝트입니다. 랜덤 장애물 그리드에서 A*를 반복 측정하되, BFS로 경로 존재를 먼저 보장해 측정 조건을 통제했습니다. 그 위에서 휴리스틱 변경, 캐시 지역성 개선, 분기 제거를 단계별로 적용하고 각 단계의 처리 시간을 비교했습니다. 즉 알고리즘 구현보다 **측정 조건 설계와 측정 기반 최적화**가 핵심인 프로젝트입니다.

## 2. 전체 포트폴리오에서의 역할

이 프로젝트는 대표 프로젝트를 뒷받침하는 기반 기술 프로젝트입니다. 앞선 P2가 멀티스레드 동시성 분석이라면, P3는 성능을 감이 아니라 측정으로 다루는 능력을 보여줍니다. 여기서 다룬 측정 조건 통제와 단계별 최적화는, 이후 P1의 FastIO/Direct IO 비교와 P4의 부하 테스트·DB 병목 분석 같은 성능 분석 흐름으로 이어집니다.

## 3. 테스트 설계

측정 결과를 신뢰할 수 있도록 조건을 통제한 것이 이 프로젝트의 핵심입니다.

- 매 반복마다 확률 기반으로 장애물을 배치한 랜덤 그리드를 생성합니다.
- 시작점과 도착점은 벽이 아닌 빈 칸에서 무작위로 선정합니다.
- BFS로 시작점에서 도착점까지 경로가 존재하는지 먼저 확인합니다.
- 경로가 없으면 그 케이스는 버리고 맵을 새로 생성합니다. 즉 경로가 존재하는 경우에만 A*를 측정합니다.
- BFS 검증 시간은 A* 측정 구간에 포함되지 않도록 분리했습니다.
- 위 조건으로 5만 회를 반복 측정해 표본을 확보하고, 극단값을 제외한 평균으로 비교했습니다.

## 4. A* 처리 흐름

README에서는 핵심 흐름만 요약합니다. 함수 단위 상세는 `docs/Code_Flow.md`로 정리합니다.

- open list(우선순위 큐)에서 f 값이 가장 작은 노드를 꺼내 확장합니다.
- 이미 확정된 노드는 close 처리해 다시 열지 않습니다.
- 이웃마다 g(시작점까지 비용), h(도착점까지 추정 비용), f(g + h)를 계산합니다.
- 각 칸에 부모 좌표를 기록해, 도착 후 부모를 거슬러 올라가며 경로를 복원합니다.

## 5. 최적화 과정

| 단계 | 변경 내용 | 목적 |
|---|---|---|
| 1. 휴리스틱 변경 | 유클리드(제곱근 포함) 휴리스틱을 8방향 이동에 맞는 형태로 바꾸고 제곱근 연산 제거 | 노드마다 반복되는 계산 비용을 줄이고, 격자 이동에 맞는 추정으로 탐색 노드 수 감소 |
| 2. 캐시 지역성 개선 | 격자 데이터 구조 크기를 줄이고, 2차원 배열을 연속 메모리로 배치 | 인접 칸 접근 시 캐시 적중률을 높여 순회 비용 감소 |
| 3. switch 제거 | 8방향 처리를 switch 분기에서 방향 오프셋·비용 테이블 참조로 변경 | 반복 루프에서 분기 비용을 줄임 |

각 단계를 아래 흐름으로 정리하면 다음과 같습니다.

- **휴리스틱 변경** — 문제: 제곱근을 포함한 휴리스틱이 노드마다 반복 계산됨. 변경: 8방향 이동에 맞는 휴리스틱으로 바꾸고 제곱근 제거. 결과: 평균 처리시간 감소. 의미: 정확도를 유지하면서 계산 비용을 줄임.
- **캐시 지역성 개선** — 문제: 격자 데이터가 흩어져 있어 캐시 미스가 잦음. 변경: 구조체 크기 축소 + 연속 메모리 배치. 결과: 추가 감소. 의미: 알고리즘뿐 아니라 메모리 배치도 성능에 영향.
- **switch 제거** — 문제: 8방향 처리를 매번 분기로 판단. 변경: 방향·비용 테이블 참조로 분기 제거. 결과: 추가 감소. 의미: 반복 루프에서 분기 제거 효과가 누적됨.

## 7. 최적화에서 확인한 점

- 경로가 없는 케이스가 섞이면 A*가 전체 격자를 탐색하는 최악 상황이 표본에 들어가 측정이 오염됩니다. 그래서 BFS로 먼저 걸렀습니다.
- 제곱근 제거는 노드마다 반복되는 계산 비용을 줄이는 데 의미가 있었습니다.
- 메모리 배치와 캐시 지역성도 실제 성능에 영향을 줍니다.
- 분기 제거는 반복 루프에서 효과가 누적됩니다.
- 최적화는 감이 아니라 단계별 측정으로 판단해야 한다는 점을 확인했습니다.
