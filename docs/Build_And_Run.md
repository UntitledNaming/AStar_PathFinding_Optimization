# Build & Run

이 문서는 README보다 자세한 빌드·실행 안내입니다. 이 프로젝트는 랜덤 맵에서 A*를 반복 측정하는 벤치마크이므로, 실행마다 결과가 달라질 수 있습니다.

---

## 1. 개발 환경

- OS: Windows
- IDE: Visual Studio 2022
- 언어 표준: C++17
- 빌드 구성: x64
- 실행 방식: Windows 응용 프로그램으로 실행하며, 자동 측정 모드에서 랜덤 맵을 반복 생성해 A*를 측정합니다. 측정은 스레드 로컬 프로파일러로 하고, 시간 측정에 Windows 성능 카운터(QueryPerformanceCounter 계열)를 사용합니다.

---

## 2. 빌드 방법

- `AStar_PathFinding/` 솔루션을 Visual Studio 2022로 엽니다.
- 빌드 구성은 x64로 설정합니다.
- Debug / Release: 성능 측정은 Release 구성으로 실행하는 것이 실측에 적합합니다(빌드 구성에 따라 절대 시간이 달라짐).
- 빌드 대상: 길찾기 응용 프로그램.

> 프로젝트 참조·구성 세부는 솔루션 설정을 따릅니다. 환경에 따라 조정이 필요할 수 있습니다. 

---

## 3. 실행 방법

- 응용 프로그램을 실행하면 자동 측정 흐름이 다음을 반복합니다.
  1. 랜덤 장애물 맵 생성.
  2. 벽이 아닌 빈 타일에서 시작점·도착점 선정.
  3. BFS로 경로 존재 검증(없으면 맵을 새로 생성).
  4. 경로가 있으면 A*를 실행하고 처리 시간을 측정.
- 위 과정을 설정된 반복 횟수(측정에서는 5만 회)만큼 수행한 뒤, 측정 결과를 파일로 저장하고 종료합니다.
- 결과 파일: `Profiling [PathFinding]_<날짜>_<시각>.txt` 형태로 생성됩니다.

> 결과 파일의 정확한 저장 경로는 실행 환경·프로젝트 설정에 따릅니다. 실행 후 생성된 Profiling 파일을 확인하세요. 

---

## 4. 결과 확인

- Profiling 결과 파일에는 태그별로 평균(Avg), 최소(Min), 최대(Max) 처리시간과 호출 수(Call)가 표 형태로 기록됩니다.
- 평균 처리시간: 극단값을 제외한 평균이며 마이크로초(μs) 단위입니다.
- 최소/최대 시간: 측정 구간의 최소·최대 값.
- 단계별 결과 비교: `길찾기 측정 자료/측정 자료/` 아래에 최적화 단계별(기본 / 휴리스틱 변경 / 캐시 히트율 높이기 / switch 제거) Profiling 결과가 정리되어 있습니다. 단계별 평균은 280.4μs → 226.1μs → 216.8μs → 195.9μs입니다(`docs/Test_Report.md`).

---

## 5. 주의사항

- 랜덤 맵이므로 실행마다 결과가 달라질 수 있습니다. 절대 시간보다 동일 환경 내 상대 개선을 기준으로 봐야 합니다.
- 경로 없는 케이스는 BFS로 필터링해야 A* 측정이 오염되지 않습니다. 자동 측정 흐름은 이 필터링을 포함합니다.
- 빌드 설정(Debug/Release)과 PC 사양(CPU·캐시)에 따라 절대 시간은 달라집니다.
- 단계별 비교는 같은 환경에서 측정한 값끼리 비교해야 의미가 있습니다.
