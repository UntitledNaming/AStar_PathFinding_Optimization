# Test Report

이 문서는 A* 성능 측정과 단계별 최적화 결과를 정리합니다. 확정된 수치만 사용합니다. 측정 자료는 `길찾기 측정 자료/측정 자료/` 아래에 단계별로 정리되어 있습니다.

---

## 1. 테스트 목적

- **A* 길찾기 성능 측정**: 랜덤 맵에서 A*의 평균 처리시간을 측정한다.
- **공정한 테스트 환경 구성**: 경로 존재 여부를 통제해, 경로 없는 최악 케이스가 측정에 섞이지 않게 한다.
- **최적화 단계별 효과 비교**: 휴리스틱 변경, 캐시 지역성 개선, switch 제거를 단계별로 적용해 비교한다.
- **반복 측정으로 평균 안정화**: 5만 회 반복으로 평균 처리시간을 안정화한다.

---

## 2. 테스트 환경

- 랜덤 장애물 그리드: 매 반복 확률 기반으로 벽을 배치한 새 격자.
- 랜덤 시작점 / 도착점: 벽이 아닌 빈 타일에서 무작위 선정.
- BFS 경로 존재 검증: 시작→도착 경로가 있는지 먼저 확인.
- 경로가 있는 경우에만 A* 수행: 경로 없는 맵은 버리고 새로 생성.
- 반복 횟수: 5만 회(측정 결과의 호출 수 Call = 50000).
- 측정 방법: A* 구간을 스레드 로컬 프로파일러로 측정하고, 극단값을 제외한 평균(트림 평균)을 마이크로초로 기록.

## 5. 추가 측정 — 휴리스틱 A/B (확장 노드 수)

3~4장의 4단계 사다리는 각 단계를 순서대로 쌓아 측정한 것이라, 휴리스틱 단계의 개선분이 "무엇 때문에" 나왔는지는 시간만으로는 분리되지 않는다. 그래서 최적화가 모두 반영된 **최종 빌드**에서, 같은 실행·같은 맵·같은 시작/도착점에 대해 h만 바꿔 두 번 돌리고 **확장 노드 수**(우선순위 큐에서 뽑혀 실제로 8방향을 펼친 노드 수)를 함께 셌다.

### 5.1 측정 조건

- 한 번의 `PathFinding` 호출 안에서 옥타일 → 유클리드 순서로 두 번 탐색한다. 맵·시작점·도착점이 완전히 동일한 **짝지은 비교**다.
- 두 구간을 각각 `PathFinding_Octile`, `PathFinding_Euclid` 태그로 프로파일링한다. BFS 선판정은 두 구간 모두의 바깥에 있다.
- 반복 5만 회, 상·하위 극단값 제외 평균.
- 근거 파일: `길찾기 측정 자료/측정 자료/기본/휴리스틱 알고리즘 변경/Profiling [PathFinding_Euclid 37823399_Octile 31352137]_20260826_21.30.59.txt`

### 5.2 결과

| 휴리스틱 | 확장 노드 수(누적) | 1회당 평균 확장 노드 | 평균 처리시간 | 
|---|---:|---:|---:|---:|
| 유클리드 | 37,823,399 | 약 756개 | 215.6μs | 
| 옥타일 | 31,352,137 | 약 627개 | 180.8μs | 
| 차이 | −6,471,262 (−17.1%) | −129개 | −34.8μs (−16.1%) | +1.2% |

- 확장 노드 −17.1%, 처리시간 −16.1%로 두 값이 거의 비슷하다. 즉 **시간 이득의 원인은 확장 노드 수 감소**로 볼 수 있다.


### 5.3 원인 

h는 그 노드에서 목적지까지의 이동 거리 추정이다. 8방향 격자에서 실제 이동은 대각(1.5)과 직선(1)의 조합이므로,

- 옥타일 `(dx+dy) − 0.5·min(dx,dy)` 는 대각 min(dx,dy)번 + 직선 |dx−dy|번의 비용 합과 정확히 같다. 장애물이 없을 때의 실제 최소 비용이다.
- 유클리드 h는 격자 제약이 없는 두 점 사이의 직선 거리라 항상 그 이하다. 

| 두 점 | 옥타일 h | 유클리드 h | 차이 |
|---|---:|---:|---:|
| (1,1) → (2,2) | 1.5 | 1.414 | 0.086 |
| (1,1) → (3,3) | 3.0 | 2.828 | 0.172 |
| (1,1) → (5,5) | 6.0 | 5.657 | 0.343 |

f = g + h이므로 목적지에서 먼 노드일수록 f가 더 많이 깎인다. 그만큼 옥타일에 비교해서 우선순위 큐에서 먼저 뽑히는 노드가 더 많아질 수 있고 따라서 탐색이 목적지 쪽으로 곧게 뻗는 대신 옆으로 퍼진다. 이것이 유클리드 쪽 확장 노드가 많아지는 이유다. 

### 5.4 해석 시 주의

- 이 측정은 **최종 빌드**에서 수행했다. 3장 표의 280.4 / 226.1μs와는 빌드가 다르므로 수치를 이어 붙이면 안 된다.
- 매 반복에서 옥타일을 먼저, 유클리드를 나중에 돌기 때문에 캐시 상태는 유클리드 쪽에 유리하다. 그런데도 옥타일이 앞서므로 위 격차는 보수적인 값이다.
- 절대 시간은 PC 사양에 따라 다르므로 같은 환경에서의 상대 비교로만 본다.

## 6. 최적화 단계별 해석

- **휴리스틱 변경(280.4 → 226.1μs)**: 유클리드는 격자 제약이 없는 직선거리라 실제 이동 비용을 낮게 추정하고, 그만큼 A*가 목표 방향에서 옆으로 더 퍼진다. 같은 비용 모델의 실제 최소 비용과 일치하는 옥타일 형태로 바꿔 불필요한 확장을 줄였다. 가장 큰 폭의 개선이 나온 단계다.
- **캐시 지역성 개선(226.1 → 216.8μs)**: 구조체 크기를 줄이고 결과 격자를 연속 메모리로 배치해, 인접 타일 반복 접근 시 캐시 적중률을 높였다. 알고리즘은 그대로지만 메모리 배치로 성능이 개선된 단계다.
- **switch 제거(216.8 → 195.9μs)**: 8방향 처리를 테이블 참조로 바꿔 분기 비용을 없앴다. 확장 노드마다 8방향을 도는 반복 루프에서 분기 제거 효과가 누적됐다.
- 각 단계가 실제 성능에 영향을 준 이유: 알고리즘 복잡도(Big-O)는 그대로여도, 추정 정확도(휴리스틱)·메모리 접근(캐시)·분기(switch)라는 요인이 실측 성능을 좌우했다.

---

## 7. 결론

- 경로 없는 케이스를 BFS로 제거해 측정 조건을 통제했다. 덕분에 A* 자체의 개선 효과를 공정하게 비교할 수 있었다.
- 메모리 접근·캐시·분기도 실제 성능에 영향을 준다는 점을 측정으로 확인했다. 이는 많은 객체·좌표·경로를 반복 처리하는 게임 서버 개발의 성능 분석과 직접 연결된다.
