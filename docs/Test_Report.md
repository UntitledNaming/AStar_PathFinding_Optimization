# Test Report

이 문서는 A* 성능 측정과 단계별 최적화 결과를 정리합니다. 확정된 수치만 사용합니다. 측정 자료는 `길찾기 측정 자료/측정 자료/` 아래에 단계별로 정리되어 있습니다.

---

## 1. 테스트 목적

- **A* 길찾기 성능 측정**: 랜덤 맵에서 A*의 평균 처리시간을 측정한다.
- **공정한 테스트 환경 구성**: 경로 존재 여부를 통제해, 경로 없는 최악 케이스가 측정에 섞이지 않게 한다.
- **최적화 단계별 효과 비교**: 휴리스틱 변경, 캐시 지역성 개선, switch 제거를 단계별로 적용해 비교한다.
- **반복 측정으로 평균 안정화**: 5만 회 반복으로 평균 처리시간을 안정화한다.

---

## 2. 테스트 환경

- 랜덤 장애물 그리드: 매 반복 확률 기반으로 벽을 배치한 새 격자.
- 랜덤 시작점 / 도착점: 벽이 아닌 빈 타일에서 무작위 선정.
- BFS 경로 존재 검증: 시작→도착 경로가 있는지 먼저 확인.
- 경로가 있는 경우에만 A* 수행: 경로 없는 맵은 버리고 새로 생성.
- 반복 횟수: 5만 회(측정 결과의 호출 수 Call = 50000).
- 측정 방법: A* 구간을 스레드 로컬 프로파일러로 측정하고, 극단값을 제외한 평균(트림 평균)을 마이크로초로 기록.

> 정확한 격자 크기·장애물 밀도·측정 PC 사양 등 환경 상세는 자료 정리 후 보강합니다. (TODO)

## 4. 성능 개선 결과

| 항목 | 개선 전 | 개선 후 | 변화 |
|---|---:|---:|---:|
| 평균 처리시간 | 280.4μs | 195.9μs | 약 30% 감소 |

- 5만 회 반복 측정 기준.
- 감소폭 약 30%는 (280.4 − 195.9) / 280.4 ≈ 0.30 기준입니다.

---

## 5. 최적화 단계별 해석

- **휴리스틱 변경(280.4 → 226.1μs)**: 8방향 이동에 맞는 휴리스틱으로 바꾸면서 대각 이동을 반영해 탐색 노드 수를 줄이고, 제곱근을 없애 노드마다의 계산 비용을 줄였다. 가장 큰 폭의 개선이 나온 단계다.
- **캐시 지역성 개선(226.1 → 216.8μs)**: 구조체 크기를 줄이고 결과 격자를 연속 메모리로 배치해, 인접 타일 반복 접근 시 캐시 적중률을 높였다. 알고리즘은 그대로지만 메모리 배치로 성능이 개선된 단계다.
- **switch 제거(216.8 → 195.9μs)**: 8방향 처리를 테이블 참조로 바꿔 분기 비용을 없앴다. 확장 노드마다 8방향을 도는 반복 루프에서 분기 제거 효과가 누적됐다.
- 각 단계가 실제 성능에 영향을 준 이유: 알고리즘 복잡도(Big-O)는 그대로여도, 계산 비용(제곱근)·메모리 접근(캐시)·분기(switch)라는 상수 요인이 실측 성능을 좌우했다.

---

## 6. 결론

- 경로 없는 케이스를 BFS로 제거해 측정 조건을 통제했다. 덕분에 A* 자체의 개선 효과를 공정하게 비교할 수 있었다.
- 최적화는 감이 아니라 단계별 측정으로 판단했다. 각 단계마다 측정하고, 효과가 확인된 변경만 남겼다.
- 알고리즘 복잡도뿐 아니라 메모리 접근·캐시·분기도 실제 성능에 영향을 준다는 점을 측정으로 확인했다. 이는 많은 객체·좌표·경로를 반복 처리하는 게임 서버 개발의 성능 분석과 직접 연결된다.
